### Arrays and Strings

- I can recognize when to use hashing versus sorting.
- I understand fixed-size and variable-size sliding windows.
- I can use prefix sums with hash maps.
- I understand when two pointers are applicable.

### Data Structures

- I can implement a linked list from scratch.
- I understand stack and queue implementations.
- I can identify monotonic stack problems.
- I can implement a heap and understand its complexity.
- I can implement a Trie.

### Algorithms

- I can derive binary search boundaries correctly.
- I can identify binary search on answer problems.
- I understand greedy proofs.
- I can construct a backtracking decision tree.
- I can identify divide-and-conquer opportunities.

### Trees and Graphs

- I can implement recursive and iterative DFS.
- I can implement BFS using a queue.
- I understand topological sorting.
- I can implement Union Find with path compression and union by rank/size.
- I understand Dijkstra and Bellman-Ford.

### Dynamic Programming

- I can define a DP state.
- I can derive recurrence relations.
- I understand memoization versus tabulation.
- I can optimize space complexity.
- I can recognize common knapsack variations.
- I can recognize subsequence and interval DP.

### Interview Skills

- I can solve unfamiliar Medium problems independently.
- I can communicate my reasoning while coding.
- I can analyze time and space complexity.
- I can test my code with edge cases.
- I can write clean code without relying on autocomplete.

# Important Notes

1. Some problems appear in multiple conceptual categories in the real world. They are intentionally assigned to their primary learning section here. The master checklist should eventually have one canonical checkbox per problem.
2. Some Premium labels can change as LeetCode changes its access policy. Verify access before relying on those problems.
3. This is a curriculum, not a requirement to solve every Hard problem before applying for internships or jobs.
4. When a problem is too difficult, study the pattern, understand the solution, and revisit it after 3–7 days.
5. A problem is not truly completed just because its submission was accepted. You should be able to reproduce and explain the solution without looking at the editorial.

**Completion standard:** Solve independently, explain the algorithm, analyze complexity, and handle edge cases.
